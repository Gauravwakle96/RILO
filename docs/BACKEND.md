# Rilo backend

> RILO 2 workspace expansion: see [implementation status](RILO_2_IMPLEMENTATION.md), [workspace API](WORKSPACE_API.md), [guide](RILO_2_GUIDE.md), and [fresh verification](RILO_2_VERIFICATION.md). Earlier scope notes below describe the preserved benchmark foundation.


Rilo runs locally with FastAPI, SQLite, a separate durable worker, and two research agents: Scout (plain Python) and Relay (LangGraph). SQLite WAL suits a single-user, single-worker application and avoids a hosted database or ongoing database fee. Authentication and storage do not implement team tenancy.

## Start and configure

From the repository directory, run `uv sync`, copy `.env.example` to a private `.env`, and run `uv run rilo serve`. For separate processes, run `uv run uvicorn rilo.api:app --host 127.0.0.1 --port 8018` and `uv run python -m rilo.worker`. Production browser assets are served from `frontend/dist` when present. Development uses the frontend's Vite server on port 5187. Restart the API and worker after editing environment variables; neither automatically reloads credentials.

`RILO_DATA_DIR` locates the SQLite database and local session key. `RILO_BIFROST_URL` is the explicitly configured loopback gateway URL, `RILO_MODEL` selects a model, and `BIFROST_API_KEY` supplies a private Bifrost virtual key in the `x-bf-vk` header. A successful gateway health check establishes reachability; authenticated model output and usage are verified during execution. `TAVILY_API_KEY` is necessary for live retrieval. `RILO_PORT` admits the corresponding local browser origin when using a custom server port. Endpoint URLs are restricted to explicit loopback hosts and ports; proxy environment variables and redirects are disabled for service calls.

Keep `.env` and `.rilo` ignored and private. Browser sessions use an HttpOnly, SameSite=Strict cookie with an in-memory CSRF token for mutations. CLI and SDK requests can use the generated `.rilo/session.key` as a bearer credential. This local design is not a substitute for authentication, tenant permissions, and TLS needed for a public deployment.

## Execution and evidence

Experiment creation persists a validated specification, immutable content-hashed manifest, and randomized attempt order before execution. The manifest pins built-in implementation, grader, and core runtime hashes plus relevant Python/dependency versions. Hashes read only fixed nonsecret package source files and are captured at process start; no credential or user-workspace content is hashed. A worker with a different loaded implementation records an infrastructure error instead of silently running the old manifest under new code. Restart both API and worker after code changes. The worker claims jobs atomically, renews a 20-second lease every four seconds, and executes one attempt at a time. Expired running experiments become partial with interrupted attempts rather than fabricated results. Cancellation preserves completed output and partial traces, cancels an in-flight coroutine, and accounts for pending attempts. Limits cap attempts, repetitions, search/model boundary calls, run duration, queued experiments, and service response sizes. Trace volume follows the bounded built-in workflows, and event streaming returns at most 500 events per batch.

The `fixture` engine executes deterministic synthesis over explicitly synthetic, CC0 evidence. It performs zero model inference, reports token counts as null with `not_applicable` provenance, and reports zero API fees. The `bifrost` engine makes actual model requests through the local gateway and never falls back to fixtures. Controlled mode uses the same synthetic evidence in both agents; live mode calls the fixed Tavily search endpoint. Live requests use basic search, at most five results, a task reference window, and returned credit usage when provided. Nested evidence fields and HTTP source URLs are validated before consumption.

Search timeout, model outage, and document prompt injection are controlled faults at observed boundaries. They do not disrupt an external service. Both agents receive the same tasks and selected scenarios; Relay has bounded retries, entity/date evidence filtering, and untrusted-document instructions. The HTTP adapter registers an explicitly local endpoint and can evaluate structured final output from another framework with controlled evidence. Live mode is rejected because the adapter does not implement an observable Tavily search boundary. It cannot inject faults or observe that endpoint's internal model/tool calls and steps; incompatible scenario selections are rejected and those metrics remain null even on adapter failures.

Steps count explicitly recorded `step` events, not hidden reasoning or arbitrary framework-internal transitions. Tool and model calls count observed attempted boundaries, including a deliberately injected unavailable response; model token usage counts actual gateway responses. A model attempt has reported token totals only when every dispatched model request has nonnegative integer prompt/completion counts. Missing, malformed, failed, interrupted, and opaque observations remain unknown. API fees default to unknown; explicit configured rates can establish an estimate under the pricing policy below. Compare step totals only with the recorded observation coverage in mind.

The deterministic grader checks required verbatim facts, cited support, matching organization, reference dates, explicit uncertainty/conflict behavior, injection exposure, and the canary. Grader `research-evidence-v2` accepts a required statement occurring as a complete token passage within a source-supported fact, including a quote with additional supported sentences. Unsupported appended claims and negation still fail source support. Historical v1 results are preserved; v1 and v2 gates are incompatible. These checks apply to structured facts; grounding of arbitrary summary claims is unassessed and recorded in assessment coverage. Each fact needs support from at least one cited source; support from additional cited sources is not separately proven. Custom tasks require at least one supported reference statement; legacy tasks without a reference rubric are inconclusive. Live citation checks alone cannot prove full task correctness, so live semantic assessment remains inconclusive without a separately validated reference rubric. Repeated comparison gates require compatible agent/task/scenario/evidence versions, gateway/cache policy, model, limits, pricing basis, completed coverage, and at least three repetitions. This is an exploratory gate with limited samples, not statistical certification.

HTTP agent version registration uses `POST /api/v1/agents/{id}/versions` with a new `version` and explicit local `endpoint`; optional name/description updates are accepted. `GET` on the same route lists registered versions. Reusing a version label is rejected. The latest registry entry supplies new experiments; existing manifests keep their original version and endpoint. An opaque endpoint's source cannot be verified, so its implementation version remains user declared. For strict comparisons, agent changes are incompatible by default. Passing `allow_agent_changes: true` to `POST /comparisons` declares differing agent/version hashes as the candidate variable while requiring unchanged IDs, framework, kind, capabilities, observation coverage, grader/core hashes, task/scenario/evidence, model, limits, and price basis. The response records the declared differences and both agent version snapshots. Missing historical implementation/pricing provenance keeps a strict gate inconclusive.

## Explicit API pricing

`RILO_MODEL_PRICING_JSON` maps exact configured model IDs to numeric `input_usd_per_million` and `output_usd_per_million` rates. Both fields are required, finite, and nonnegative; booleans, strings, missing/extra fields, invalid JSON, and nonfinite or negative rates are rejected. The default `{}` keeps real model fees unknown. An explicit local rate can be configured only after verifying that provider's billing policy:

```dotenv
RILO_MODEL_PRICING_JSON={"ollama/qwen2.5-coder:7b":{"input_usd_per_million":0,"output_usd_per_million":0}}
```

Creation copies the selected rates, units, model identity/match policy, and coverage into an immutable manifest `price_basis`. The worker uses that snapshot even if configuration later changes. Fees are `input_tokens * input_rate / 1_000_000 + output_tokens * output_rate / 1_000_000`, labeled `estimated`, including explicit zero. Every dispatched response must have reported usage and match the requested model: an exact provider-qualified response model, or the unqualified model plus a matching response provider. Contradictory provider/routing/resolved-model metadata, a fallback model, missing identity, incomplete usage, or HTTP opacity keep fees null. Local-looking names cannot establish zero pricing. Estimates cover model-token fees only; they exclude Tavily credits, hardware, energy, discounts, cache-specific billing adjustments, and provider statements. Earlier reports are never retroactively priced.

JSON exports retain every attempt, manifest, output, and trace. CSV exports contain scalar metrics with spreadsheet-formula escaping. Sensitive fields and known credentials are redacted. Current schemas validate requests and model outputs, but not every API route declares an explicit Pydantic response model. Team accounts, isolated remote workers, instrumentation of arbitrary third-party agents, billing measurements, and live semantic reference rubrics remain future work.

## Credit allowance and checks

`RILO_TAVILY_CREDIT_LIMIT` is a conservative lifetime allowance for the local workspace. Admission reserves each live experiment's maximum search-call budget across all attempts and checks accumulated reservations. Reservations are not reconciled with completed search usage and do not reset monthly. Raising this setting can permit additional external usage; it does not describe remaining provider credits or measured spend.

Run `uv run ruff check backend/rilo tests/backend tests/developer`, `uv run mypy backend/rilo`, and `uv run pytest`. Tests exercise the full 120-attempt fixture matrix, cancellation/recovery, resource limits, authentication/CSRF, untrusted external response shapes, missing usage, adapters, reference grading, comparison compatibility, and full-size exports. Mocked service tests verify the integration contract; they do not establish live provider acceptance. Actual Bifrost and Tavily run results must be reported separately from fixture and mocked checks.
